# Герби-Марафон — нормативный scope пилота

## Цель

Проверить ежедневный командный сценарий внутри существующего AI-худеетора без
переименования приложения и без построения общей социальной сети.

## Основной пользовательский путь

1. Завершённый пользователь входит в конкретный марафон и ровно одну команду.
2. Вес вводится и исправляется только через существующий tracking daily upsert.
3. Пользователь отправляет отчёт **за вчера** по восьми фиксированным отметкам.
4. Капитан публикует отдельное задание на локальную дату команды.
5. Участник отмечает или отменяет выполнение задания.
6. Экран команды получает только дневные, безопасные производные результаты.

## Восемь отметок отчёта

1. Утренний коктейль.
2. Физическая активность.
3. Норма воды.
4. Второй коктейль.
5. Здоровый ужин.
6. Хороший сон.
7. Никакой вредной еды.
8. Никакого курения.

Отчёт отсутствует, пока пользователь его не отправил. Отсутствие отчёта —
`unknown`, а не нулевой результат. Повторная отправка за ту же дату обновляет
тот же отчёт.

## Три независимых показателя

- дневной процент веса: `(вес вчера − вес сегодня) / вес вчера × 100%` только по точным соседним локальным датам;
- дневной Веллнес показатель: один балл за каждую из восьми отметок (`0..8`);
- выполнение задания капитана, которое участник отмечает сам.

Общий score, веса показателей и единый победитель запрещены. Накопленные итоги
марафона не выдаются командному API. Задание капитана не является девятой
отметкой Веллнес отчёта. При равном значении участники занимают общее место и
показываются одной группой; произвольный победитель не выбирается.

Стартовый вес фиксируется один раз по первой актуальной дневной записи
пользователя внутри периода марафона. Последующее исправление daily weight не
меняет уже зафиксированный baseline. Для дневного процента отсутствие точной
записи вчера или сегодня означает `unknown`; более старая запись не подставляется.

## Доступ и приватность

- участник видит только команду, в которой состоит;
- капитан имеет полномочия только внутри своей команды;
- командный read model не содержит raw weight, AI conversation, AI memory,
  email или иных скрытых профильных данных;
- API возвращает только дневные производные метрики, разрешённое display name и
  состояние отчёта/задания;
- создание тестового марафона выполняется только через явно включённый
  bootstrap-контур; stable по умолчанию его не включает.

## AI и согласие

GenAPI остаётся за существующим `AiProviderAdapter`. Внешний запрос разрешён
только после сохранённого `aiProviderProcessing` consent актуальной версии.
Fake adapter сохраняется. Timeout после возможной передачи провайдеру остаётся
`outcomeUnknown` и не считается безопасным повтором.

## Не входит

- публичная социальная сеть, лента, реакции и передача токенов;
- общий рейтинг или накопленный командный итог;
- доступ капитана к raw weight, чату или памяти;
- полноценная admin platform;
- push, cron и уведомления;
- food photo/vision в основном scope пилота.

## Открытые решения

До ответа владельца не создаются реальные даты марафона, состав команд и
назначение капитанов. Накопленные итоги и единый общий score не вычисляются.

## Food vision — отдельный последующий объём

Фото еды не входит в текущую реализацию марафона. До его добавления необходимо отдельно принять и реализовать:

- приватную загрузку в S3-compatible storage и короткоживущие signed URLs;
- MIME/размер validation, quarantine/malware boundary, lifecycle, retention и удаление оригинала;
- provider-neutral vision contract и отдельное решение о vision-capable provider;
- цену действия, reservation/confirmation/refund и поведение при `outcomeUnknown`;
- схему результата с неопределённостью распознавания и пользовательской коррекцией;
- privacy/consent, безопасные logs и запрет передачи изображения через analytics/outbox.

До закрытия этих зависимостей изображение не считается анализом блюда и не должно импровизироваться внутри марафонного endpoint или AI quick reply.
