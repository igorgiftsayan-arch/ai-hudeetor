# UI-001 — ручная приёмка ежедневной фиксации веса

## Предусловия

- изолированная test-server topology использует verification commit ветки `ui/ui-001-daily-weight`;
- web, API, PostgreSQL и Redis healthy, актуальные migrations уже применены;
- создан совершеннолетний test user с `onboarding_status=completed`, тестовым token balance и несколькими weight entries;
- browser API доступен только через same-origin `/api/v1`, а API, worker, PostgreSQL и Redis не публикуют host ports;
- проверка выполняется в mobile viewport и на desktop.

## Основной сценарий

1. Открыть `/login`, ввести тестовые email и пароль и проверить disabled-кнопку `Входим…` во время запроса.
2. Убедиться, что completed user перенаправлен на `/today`.
3. Проверить сегодняшнюю дату, последний вес, нейтральное изменение и недавнюю историю.
4. Ввести вес с запятой, например `98,4`, и нажать `Сохранить вес`.
5. Во время запроса проверить disabled-кнопку `Сохраняем…`.
6. После ответа проверить спокойное подтверждение `Записано`, новый последний вес и новую строку истории.
7. Обновить страницу и убедиться, что запись загружена из существующего weight API.
8. Открыть `Поговорить с AI` и нижнюю вкладку `AI`; убедиться, что `/quick-reply` доступен напрямую и вкладка `Сегодня` возвращает на `/today`.

## Негативные сценарии

1. Ввести `98,45`: UI должен показать validation error и не отправить POST.
2. Прервать сеть на первом POST, затем восстановить её и нажать `Повторить сохранение`: должен повторно использоваться тот же `Idempotency-Key`, а в истории должна остаться одна запись.
3. Прервать сеть до загрузки страницы: показать спокойную ошибку и рабочую кнопку `Попробовать снова`.
4. Ввести неверный пароль на `/login`: показать понятную ошибку без раскрытия существования аккаунта.
5. Очистить/просрочить session cookie: `/today` должен перенаправить на `/login` без отображения персональных данных.
6. Проверить пользователя без записей: показать `Здесь появятся ваши изменения. Начните с сегодняшнего веса.`

## Definition of Done applicability

- Код и web tests: применимо.
- Миграции: N/A — схема и backend не меняются.
- API documentation/contracts: N/A — используются существующие endpoints без изменения DTO.
- Analytics events: N/A — новые frontend events не создаются; `weight_added` уже возникает на backend.
- Ownership: применимо и остаётся server-side в существующем weight API.
- Test server: применимо; отдельный Compose project `atlas-ui-001` публикует только gateway/web port `3100`.

## Результат 2026-07-22

- Основной browser-сценарий выполнен Chromium mobile против реального API: completion, empty state, save `98,4`, `Записано`, reload persistence и переход в AI.
- Component tests подтверждают latest/history, validation, loading/error/retry, session expired, disabled state и стабильный ключ сетевого повтора.
- Визуально проверен mobile viewport: главное действие, summary и история читаемы; AI остаётся вторичным действием.
