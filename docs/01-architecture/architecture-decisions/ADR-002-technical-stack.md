# ADR-002: технический стек

- Статус: предложено; решение отложено до ARCH-001
- Дата: 2026-07-18

## Контекст

DOC-002 определяет требования, но прямо запрещает автоматический выбор стека. Поэтому принятое на этом этапе решение — не фиксировать технологии до сравнительной оценки в ARCH-001 и не начинать реализацию раньше её завершения.

## Требования

- Монорепозиторий с явными границами PWA frontend, backend, общих контрактов и инфраструктуры.
- PostgreSQL, Redis, S3-совместимое хранилище, миграции и транзакционные операции.
- Типобезопасные/валидируемые API-контракты и единый формат ошибок.
- PWA, адаптивность, доступность и поддержка актуальных мобильных браузеров.
- Фоновые задачи, идемпотентность, наблюдаемость, audit log и тестируемые адаптеры внешних сервисов.
- Локальная воспроизводимость, CI, test deployment и отсутствие vendor lock-in для AI.

## Критерии выбора

1. Компетенции и скорость небольшой команды.
2. Корректность типов, транзакций и миграций.
3. Зрелость security, testing, PWA и observability tooling.
4. Простота эксплуатации на тестовом сервере и прогнозируемая стоимость.
5. Поддерживаемость монорепозитория, обновлений и найма.
6. Возможность заменить AI, аналитику, платежи и S3-провайдера через адаптеры.

## Рассматриваемые варианты

- **TypeScript end-to-end:** React/Next.js или Vue/Nuxt для PWA; Node.js framework для API; зрелая общая типизация, но требуется дисциплина runtime-валидации и транзакций.
- **TypeScript frontend + Python backend:** React/Vue и FastAPI/Django; сильная AI-экосистема, но два языка и дублирование контрактов увеличивают сложность.
- **TypeScript frontend + Go backend:** компактный и эффективный backend; выше порог продуктовой итерации и интеграции AI для небольшой команды.

Внутри каждого варианта ARCH-001 должна сравнить минимум два реалистичных набора фреймворков, ORM/query layer, миграций, тестов и monorepo tooling на одной таблице критериев и коротком spike без бизнес-функций.

## Принятое решение

**Выбор отложен до ARCH-001.** DOC-002 не выбирает язык, framework, ORM, API style, auth/session, CI/CD, контейнеризацию, hosting, analytics, payments, S3 или AI-провайдера.

## Причины отказа от альтернатив

Альтернативы пока **не отклонены**: без подтверждённых ограничений команды, сервера и сравнительного spike причины отказа были бы вымышленными. ARCH-001 обязана для выбранного варианта зафиксировать измеримые причины выбора, а для каждого отклонённого — конкретные trade-offs. AI-провайдер остаётся предметом отдельного ADR.
