# ADR-002: единый TypeScript-монорепозиторий

- Статус: принято
- Дата: 2026-07-18

## Контекст и критерии

V1 должна быстро доставляться малым составом и Codex, поддерживать PWA, API, AI-оркестрацию и последующий найм. Оценивались скорость MVP, поддержка, AI-интеграции, удобство Codex, эксплуатационная стоимость, рынок разработчиков, масштабирование, документация и зрелость.

## Решение

Использовать `pnpm workspace` и единый TypeScript-контур: Next.js/React для frontend, NestJS для API и worker. PostgreSQL, Redis и private S3 образуют data/infrastructure boundary. Точные версии и библиотеки фиксирует BOOT-001.

## Альтернативы

- React/Vite + FastAPI: сильная Python AI-экосистема, но два языка и дублирование tooling/контрактов.
- Nuxt + NestJS: технически пригодно, но не даёт преимущества над выбранным вариантом по рынку и экосистеме.
- React + Django: зрелые ORM/admin, но два стека и лишнее сцепление с framework-моделью.
- Go backend: эффективный runtime, но ниже скорость продуктовой итерации и AI-интеграций для V1.

## Ограничения и последствия

Shared packages не содержат ORM или бизнес-логику. Единство языка не отменяет runtime-валидацию и DB constraints. Микросервисы, Kafka, Kubernetes, CQRS/event sourcing, vector database и warehouse не используются.

Python-компонент допустим позже только при измеримом Python-only ML/CV/data workload, стабильном provider-neutral контракте и выгоде выше стоимости второго runtime. Он не владеет auth, ledger, платежами, рефералами или бизнес-истиной.
