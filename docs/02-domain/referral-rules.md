# Реферальные правила

## Механика

Пользователь делится персональной ссылкой. При регистрации связь фиксирует одного пригласившего и неизменна. После выполнения порога оба участника однократно получают по **100 токенов**.

## Порог приглашённого

Все условия обязательны:

1. Завершить онбординг.
2. Проявить учитываемую активность минимум в **5 разных календарных днях** в реферальном окне.
3. Внести вес минимум 3 раза.
4. Выполнить минимум 1 AI-действие со статусом success.

## Реферальное окно и активный день

Окно включает **10 календарных дат**: локальную дату регистрации и следующие 9 локальных дат. Локальная дата определяется по часовому поясу, сохранённому при регистрации; последующая смена часового пояса не пересчитывает окно. После конца десятой даты прогресс перестаёт изменяться: выполненный порог награждается, невыполненный закрывается без бонуса и не продлевается.

Активным считается календарный день, в который backend подтвердил хотя бы одно из событий: сохранение веса, параметра тела, утреннего/вечернего чек-ина, простой спортивной активности или успешное AI-действие. Несколько действий в один день дают один активный день. Онбординг, открытие экрана, login, frontend-событие и техническая ошибка активностью не считаются.

AI-действие — backend-операция из управляемого каталога `AiActionPrice`, завершившаяся сохранённым полезным результатом и событием `ai_response_success` либо соответствующим success-событием анализа. **Бесплатный быстрый AI-ответ считается**, если он успешно завершён; цена 0 не отменяет активность. Timeout, недоступность провайдера, ошибка загрузки и другие технические ошибки не считаются. Дизлайк или субъективно слабый результат не отменяет уже успешное действие.

## Защита и начисление

- Один пользователь имеет только одного пригласившего.
- Самоприглашение запрещено.
- Повторное начисление невозможно даже при повторной обработке события.
- Награды обоим начисляются одной атомарной операцией либо восстанавливаются идемпотентно.
- Подозрительную связь администратор может заблокировать вручную с обязательными причиной и аудитом; правила автоматического antifraud в V1 не добавляются.

Связанные события определены в [реестре аналитики](../04-analytics/event-registry.md).
